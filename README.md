# 动态服务暴露面与漏洞识别系统

本仓库当前实现单机扫描闭环中的这些部分：

- 授权校验。环回、链路本地和 `169.254.169.254` 只有在选择器完全落在受保护地址空间内时才允许连接。连接前对计划快照中的已解析地址再次校验，并带上产生该地址的主机名。`valid_until` 过后，领取前把授权状态改为 `expired`。
- 本地预算账本。有效上限取各层预算中更严格的值。速率等待被取消时，尚未拨号的连接计数和尚未发出的请求计数会释放。
- TCP Connect 扫描。同一地址上的并发连接数取授权里的 `max_concurrency`。超时记为 `no_response`，连接拒绝记为 `closed`。授权同时包含 `discovery` 和 `connect` 时，每个端口由端口扫描拨号一次，主机发现汇总这次结果，不对同一端口再次连接。TCP 没有证明可达时，本机网段内的 IPv4 先发送一条 ARP，否则发送一条 ICMP Echo。授权只有 `discovery` 时也按这个顺序选择；ARP 和 ICMP 都无法发送时才对授权端口做 TCP Connect。单一方法的 `no_response` 不改写成离线。权限不足记为 `unsupported`。
- HTTP、TLS、SSH、FTP、SMTP、MySQL、PostgreSQL、Redis、MongoDB、TDS、TNS、CQL、Bolt、Memcached 和 ClickHouse 有界探测。开放端口都会探测 HTTP、TLS 和 SSH。只有端口 21 额外选择 FTP。端口 25 和 587 以明文读取 SMTP 问候，端口 465 先完成 TLS 握手再读取问候。SMTP 不发送 EHLO、HELO 或 STARTTLS，最多读取 1000 字节。第一行应答码是 220 或 554、后接空格或连字符，且文本包含 smtp 时才记为 SMTP。FTP 的 220 文本不记为 SMTP。只有端口 3306 额外选择 MySQL。MySQL 不发送认证，最多读取 256 字节的一个握手包。序列号为 0、协议字节为 10，且其后有非空 NUL 结尾的服务器版本时才记为 MySQL。版本文本原样保存，不据此判断发行方。只有端口 5432 额外选择 PostgreSQL。PostgreSQL 发送一条协议 3.0 启动消息，参数只有 `user=vesper`，不发送口令、查询或后续消息。第一条后端消息最多读取 1024 字节。类型必须是 R 或 E，长度字段必须与实际字节数一致。R 是认证请求，E 是错误应答。认证方法为 0 时也立即停止，不使用已经建立的会话。服务类型 `postgresql` 表示线协议，不表示发行方。只有端口 6379 额外选择 Redis，不探测 TLS。Redis 发送一条没有参数的 RESP `PING`，不发送 AUTH、INFO 或其他命令。第一条应答最多读取 2048 字节，并且必须是一条以 CRLF 结束的 RESP 行。整行等于 `+PONG`、整行等于 `-NOAUTH Authentication required.`，或以 `-DENIED Redis is running in protected mode` 开头时才记为 Redis。其他错误和批量字符串不记为 Redis。服务类型 `redis` 表示线协议，不表示发行方。只有端口 27017 额外选择 MongoDB，不探测 TLS，也不协商压缩。MongoDB 发送一条 OP_MSG `ping`，正文只有 `ping` 和 `$db`，不发送凭据、查询或后续消息。第一条应答最多读取 1024 字节。长度字段必须与实际字节数一致，`responseTo` 必须等于请求 ID，opcode 必须是 2013。正文必须有且只有一个 kind 0 文档，并且该文档的 `ok` 为 0 或 1。`ok` 为 0 时立即停止。压缩报文和 OP_QUERY 不记为 MongoDB。服务类型 `mongodb` 表示线协议，不表示发行方。只有端口 1433 额外选择 TDS，不探测 1434，也不协商 TLS。TDS 发送一条 PRELOGIN，加密能力声明为不支持，不发送 LOGIN7。第一个包最多读取 512 字节。包类型必须是 0x04 或 0x12，状态必须带 EOM，长度字段必须与实际字节数一致。选项区必须以 0xFF 结束，并且同时包含长度为 6 的 VERSION 和长度为 1 的 ENCRYPTION。ENCRYPTION 为 0x03 时也立即停止。版本字段写成点分文本，不据此判断发行方。服务类型 `tds` 表示线协议，不表示发行方。只有端口 1521 额外选择 TNS，不探测 2484，也不跟随重定向。TNS 发送一条 CONNECT，连接数据只有 `(CONNECT_DATA=(COMMAND=ping))`，不发送口令或服务名。第一个包最多读取 1024 字节。包类型必须是 ACCEPT、REFUSE、REDIRECT 或 DATA，长度字段必须与实际字节数一致，并且包内包含 `(DESCRIPTION=`。VSNNUM 按五个字段写成点分文本。没有 VSNNUM 或 ERR 时仍可确认线协议。服务类型 `tns` 表示线协议，不表示发行方。只有端口 9042 额外选择 CQL，不探测 9160，也不协商压缩。CQL 发送一条协议版本 4 的 STARTUP，选项只有 `CQL_VERSION=3.0.0`，不发送认证响应或查询。第一帧最多读取 512 字节。应答的方向位必须置位，协议版本必须是 3、4 或 5，标志和流号必须是 0，长度字段必须与实际字节数一致。READY 的正文必须为空。AUTHENTICATE 的正文必须是一条非空字符串，此后立即停止。压缩、跟踪和 ERROR 帧不记为 CQL。服务类型 `cql` 表示线协议，不表示发行方。只有端口 7687 额外选择 Bolt，不探测 7474 或 7688，也不协商 TLS，也不使用 manifest 握手。Bolt 发送 4 字节标识 `60 60 B0 17` 和四条版本提议：5.8 及其向下 8 个次版本、4.4 及其向下 4 个次版本、4.1、3.0。不发送 HELLO 或认证。应答只读取 4 字节。保留字节和 range 必须是 0，并且主次版本必须落在上述提议范围内。全 0 表示没有匹配的版本，不记为 Bolt。服务类型 `bolt` 表示线协议，不表示发行方。只有端口 11211 额外选择 Memcached，不探测 UDP，也不协商 TLS 或 SASL。Memcached 发送一条 `version` 命令，不发送 stats、get 或 set。第一条应答最多读取 128 字节，并且必须是一条以 CRLF 结束的行。整行必须是 `VERSION ` 后接一个非空、不含空格的可打印 ASCII 版本标记。ERROR 和其他命令应答不记为 Memcached。版本标记原样保存，不据此判断发行方。服务类型 `memcached` 表示线协议，不表示发行方。只有端口 9000 额外选择 ClickHouse 原生协议，不探测 8123、9004 或 9440，也不协商 TLS。ClickHouse 发送一条 Hello，客户端名和用户名都是 `vesper`，数据库和口令都为空，客户端协议修订号是 0。不发送查询、Ping 或 addendum，也不改用其他用户重试。即使服务器接受了这条 Hello，探针也立即关闭连接。第一条应答最多读取 1024 字节。包类型 0 是 Hello：服务器名必须是非空可打印 ASCII，主版本至少是 1，其后是次版本和协议修订号。包类型 2 是 Exception：小端 int32 错误码、由大写字母数字和下划线组成的错误名、非空消息、堆栈和值为 0 的 nested 标志必须完整。其他包类型不记为 ClickHouse。服务器名和异常消息不提取为产品。服务类型 `clickhouse` 表示原生线协议，不表示发行方。端口号不直接决定服务身份。协议观察记录探针版本、实际连接地址、传输协议、请求轮次、响应字节数和证据摘要。FTP 问候、SMTP 问候、Redis 应答和 Memcached 应答的内容类型是 `text/plain`。MySQL 握手、PostgreSQL 启动应答、MongoDB 应答、TDS PRELOGIN、TNS 应答、CQL 帧、Bolt 握手应答和 ClickHouse 应答的内容类型是 `application/octet-stream`。
- DNS over UDP。端口 53 发送有界 DNS 查询。有主机名时查询该名称的 A 记录，否则查询根的 NS 记录。响应必须事务 ID 相同、QR 为 1 且 opcode 为 0。超时再发一次，仍无响应记为 `no_response`。ICMP 端口不可达记为 `closed` 且不重试。响应不匹配记为 `unknown`。没有注册探针的 UDP 端口不发送报文，端口结论是 `unknown`，观察 `result_status` 是 `not_scanned`。UDP 探针必须在发送前声明请求、长度、响应识别、ICMP 结论、超时结论和尝试次数。超时不能写成 `closed`。报文计入 `max_requests`。匹配响应的内容类型是 `application/dns-message`。指纹包 `builtin-14` 对 DNS、FTP、SMTP、MySQL、PostgreSQL、Redis、MongoDB、TDS、TNS、CQL、Bolt、Memcached 和 ClickHouse 只记录服务类型，不生成产品。`builtin-1` 到 `builtin-13` 仍按原内容发布。
- 已发布指纹规则和配置规则。指纹规则只解释已有观察，端口号不产生产品。未声明证据类型时只读取协议观察。不同服务类型分别保留。同一服务的不同产品或不同非空版本记为 `conflict`，并把对方的支持观察写入 `contradicting_observation_ids`。排除条件命中时不从该规则提取产品；同一服务已有候选时记为 `conflict`。调用方可以提交 `nmap-service-probes`。注释中的许可说明会保存。发布后，新扫描在计划里冻结该版本；弃用只影响之后的扫描。只有与现有 HTTP、SSH、FTP、SMTP 或 MySQL 观察等价、并且正则可以执行的匹配，才对照已校验的原始响应提取产品。探针载荷不发送，端口和 `Exclude` 不产生产品。配置规则接受调用方提交的 `vesper-config`。条件只比较已经采集的字段，不执行命令。未发布的规则包不进入扫描；发布后新扫描在计划里冻结该版本，弃用只影响之后的扫描。事实缺失、未请求或权限不足是 `insufficient_evidence`，不能写成通过。适用条件不成立是 `not_applicable`。pass 与 fail 同时成立是 `conflict`，同时不成立是 `unknown`。只有 `confirmed` 归并配置 Finding。内置 `host_identity_present` 仍检查 `name`，`builtin-1` 正文不改。不导入 CIS、XCCDF 或 OVAL。主动检测只运行调用方提交、结构校验通过并发布的 Nuclei HTTP 模板。扫描创建时冻结当时已发布且启用的模板。HTTP 观察成立后才创建执行单元。隔离未证明或本机没有 Nuclei 时结果是 `skipped`，不启动进程。输出里的模板标识和目标地址必须与本次调用一致，否则结果是 `conflict` 并且不生成 Finding。评估运行的 `result_summary` 统计该次评估实际产生的候选数量和检测状态数量。
- 服务候选和版本适用性判断。唯一产品别名才绑定产品身份。`generic`、`deb`、`rpm` 解析成功时写入规范化版本，原始版本保留。没有别名、多个产品别名或其他生态不绑定产品，也不生成规范化版本。`generic` 使用点分数字比较，`deb` 使用 Debian 版本比较，`rpm` 使用 RPM EVR 比较。无法按对应规则解析的版本返回证据不足。NVD、OSV、CISA KEV 和 EPSS 文档可以导入。导入先校验来源、结构和分数，通过后写入情报语句；内容变化时保留旧语句并发布新的情报快照。扫描运行创建时冻结当时的快照。重新评估只读取指定快照，追加新的评估结果，不改写已有观察和已有检测结果。存在配置或平台约束时，版本落入区间也记为证据不足。
- Finding 与 FindingOccurrence 分离。相同漏洞标识在不同端点上保持不同 Finding。Finding 的 `last_occurrence_id` 指向最近一次发生记录。漏洞 Finding 记录受影响产品，配置 Finding 记录规则标识。配置检测结果保存规则标识、规则版本和规则自身的严重性。漏洞适用性使用独立的 `vulnerability` 评估，配置判断使用 `config` 评估，服务识别使用 `service_identification` 评估。确认的漏洞检测结果引用已校验证据。处置记录追加保存，不改写检测结果和发生记录。`accept_risk` 与 `exception` 投影为 `accepted`，`suppress` 与 `false_positive` 投影为 `suppressed`。`resolve` 要求同一漏洞和主体上存在更晚的 `not_vulnerable` 检测，且该检测引用非空的已校验证据；检测标识写入处置 `scope`。新的确认发生会把已解决的 Finding 投影为 `reopened`。`POST /api/v1/findings/{id}/verification` 按 Finding 和最近一次发生记录创建触发类型为 `verification` 的复核扫描。端点复核只覆盖该端点的地址、传输协议和端口，不采集主机。配置复核只执行原规则声明的那一项采集。复核使用新的授权校验和新的预算账本，扫描完成不改变 Finding 状态；关闭仍要单独写入 `resolve`。授权的创建、审批、撤销和到期各写一条修订，并保存当时的授权内容。管理接口上的创建、审批、撤销和处置使用当前登录会话的管理员标识。管理员标识和未到期会话写入 PostgreSQL，进程重启后同一令牌仍然有效。会话写入失败时不签发令牌。口令不入库，会话有效期是 12 小时。到期审计的操作者是本机 Worker。`POST /api/v1/findings/{id}/dispositions` 写入处置，`GET /api/v1/findings/{id}/dispositions` 读取该 Finding 的处置记录。
- 本机 Linux 采集：操作系统、接口、监听套接字、进程、systemd 服务、RPM 或 dpkg 软件包，以及 nft 或 iptables 防火墙。没有对应系统接口时该操作是 `unsupported`，权限不足是 `permission_denied`。非 Linux 的全部采集操作返回 `unsupported`。采集状态写入观察值的 `collection_status`。观察的 `result_status` 只使用 `observed`、`no_response`、`unreachable`、`not_scanned`、`unsupported`、`error`、`partial`。观察的 `source_identity` 是产生该事实的本地 Worker。主机采集在识别到机器标识后写入 `asset_id`。
- 证据文件按临时文件、摘要、同步和原子改名发布。存储后端是 `local_fs`，存储键是相对对象键。协议响应在摘要校验后记为 `verified`。HTTP 和 SSH 的类型是 `raw_response`，TLS 证书的类型是 `tls_certificate`。内容编码是 `identity`，因为文件保存的是未压缩原始字节。HTTP 响应的内容类型是 `application/http`，TLS 证书是 `application/pkix-cert`，SSH 标识行、FTP 问候、SMTP 问候、Redis 应答和 Memcached 应答是 `text/plain`，DNS 响应是 `application/dns-message`，MySQL 握手、PostgreSQL 启动应答、MongoDB 应答、TDS PRELOGIN、TNS 应答、CQL 帧、Bolt 握手应答和 ClickHouse 应答是 `application/octet-stream`。设计要求证据带有敏感级，但没有规定协议响应属于哪一级，因此这些内容记为 `internal`。确认的漏洞发生记录只引用已校验证据。本机观察点记录当前架构、网络接口和能力快照，并在保存节点状态时更新最近在线时间。能力快照把已声明能力记为 `available`，记录 ICMP Echo 与 ARP 套接字权限，主动检测隔离记录本次探测结果，不能证明时为 `not_verified`，并且不改主机网络。位置标签没有输入来源，保持为空。创建扫描时把当时的观察点标识、能力快照标识和网络接口写入该运行的计划快照，后续观察点更新不覆盖这份记录。路由表没有采集。

控制服务入口是 `cmd/vesperd`。HTTP 请求只创建任务和读取结果，扫描单元由独立循环领取。启动前需要设置 `VESPER_ADMIN_USER`、`VESPER_ADMIN_PASSWORD` 和 `VESPER_DATABASE_URL`。可选 `VESPER_NUCLEI` 是 Nuclei 程序的绝对路径；没有设置时在 `PATH` 中查找。服务启动时按文件名顺序执行 `migrations` 目录中的 SQL。默认监听 `127.0.0.1:8077`。

每次新的 TCP 连接和 UDP 报文发送前都会续期当前租约，并把这次续期写入对应 StageAttempt 的 `heartbeat_at`。租约或 fencing token 已经失效时不再拨号或发送。取消后的运行同样不再拨号或发送。尝试结束时，`resource_usage` 记录该尝试相对预算账本的连接数、请求数、证据字节数和耗时，`result_digest` 是该尝试观察内容的摘要。没有观察时不写 `result_digest`。ScanUnit 的 `result_summary` 记录该尝试的观察数量和状态分布。

创建扫描时先提交 `planning` 运行和计划输入。普通扫描的触发类型记为 `manual`，修复复核记为 `verification`。`effective_budget` 保存创建时的授权预算上限，不随后续消耗变化。当前没有单独的任务预算策略，因此快照就是授权上限。域名解析成功后写入 `dns_resolution` 观察，来源种类是 `network`，并把通过授权的地址写入该运行的计划快照。后续连接只对这些快照地址沿用域名授权。计划阶段校验实际拨号使用的操作：授权包含 `connect` 时校验 `connect`，只有 `discovery` 时校验 `discovery`。传输协议为 `udp` 时校验 `protocol_probe`，只创建 `udp_probe` 单元，不创建 TCP 端口扫描和主机发现。域名解析被取消或超时时运行保持 `planning`，下一次领取会重新解析并再次校验。已经判定的计划失败会把该运行标为 `failed`。Go 标准库解析器不返回 TTL，也不返回逐跳 CNAME 链，因此观察只记录实际拿到的地址、记录类型和最终规范名，不补写 TTL。领取、租约、fencing token 和结果提交在同一个数据库事务中锁定 `scope_grant`、`scan_run` 和 `scan_unit` 后更新。观察幂等键包含 `scan_run_id`、`scan_unit_id`、`stage_key`、观察类型、主体和内容摘要，不以 `attempt_id` 作为唯一键。取消之后不再创建协议探测单元。授权不再有效的排队单元会被跳过，运行根据现有汇总规则结束。

TCP 连接和 UDP 请求在拨号或发送前写入扫描运行的预算计数。写入取较大值，较新的较小计数不能把它改小。持久化失败时不发起网络操作，并归还这次尚未执行的计数。预算耗尽不会重试。短暂的证据存储失败会在尝试次数上限内重试。

版本适用性结果的 `executor_type` 写为 `applicability`。设计列出的执行器是 `nuclei`、`native_probe`、`config_engine` 和 `fingerprint_engine`，版本区间判断不属于这四类，因此没有改名充数。配置规则命中时使用规则自己的 `severity`。漏洞 Finding 的 `severity` 只使用情报语句上已经规范化的等级。来源没有给出 `info`、`low`、`medium`、`high` 或 `critical` 时保持空字符串。CVSS `NONE` 不改写成 `info`。KEV 和 EPSS 只随来源语句保存，不参与是否受影响的判断，也不换算成风险分。

## 尚未接入的设计要求

管理界面、远程 Worker 和远程 Agent 尚未实现。Nmap 操作系统指纹库不导入，服务探针载荷不发送。Nuclei 模板不从外部网络下载。没有 HTTP-over-TLS 观察时不安排 HTTPS 主动检测。情报导入读取调用方提交的 NVD 2.0、OSV、CISA KEV 或 EPSS 文档，不从外部网络拉取，也没有厂商公告和发行版公告适配器。重新评估不创建补充采集任务，设计没有给出证据过期时限，新的扫描仍要单独授权。授权包含 `connect` 时，发现单元汇总端口扫描结果，不对同一端口再次拨号。域名登记使用 IDNA2008 Lookup，把 Unicode 名称转成 A-label 后再参与授权比较。除 DNS 以外的 UDP 协议探针尚未接入。除 MySQL、PostgreSQL、Redis、MongoDB、TDS、TNS、CQL、Bolt、Memcached 和 ClickHouse 以外的数据库协议探针尚未接入。ClickHouse 探针只发送一条 Hello，不发送查询或 addendum，也不协商 TLS。Memcached 探针只发送一条 version，不发送 stats、get 或 set，也不协商 TLS 或 SASL。Bolt 探针只发送一次版本协商，不发送 HELLO 或认证，也不协商 TLS，也不使用 manifest 握手。CQL 探针只发送一条 STARTUP，不发送认证响应或查询，也不协商压缩。TNS 探针只发送一条 COMMAND=ping，不发送口令，也不跟随重定向。TDS 探针只发送一条 PRELOGIN，不发送 LOGIN7，也不协商 TLS。MongoDB 探针只发送一条 OP_MSG ping，不发送凭据或查询，也不协商压缩和 TLS。Redis 探针只发送一条 RESP PING，不发送 AUTH、INFO 或其他命令，也不探测 TLS。PostgreSQL 探针发送一条启动消息，不发送口令或查询。MySQL 探针不发送认证。SMTP 探针不发送 EHLO，也不执行 STARTTLS。ICMP 端口不可达只作为 DNS 探针已经定义的关闭结论，不作为主机发现方法。两个控制进程同时写同一数据库时，Finding 等非任务聚合仍可能互相覆盖。设计列出了 ScanUnit 级预算，但没有给出单阶段的数量上限，因此执行端只执行授权上的运行级预算和探针自身的超时、字节数限制，没有另设一套单元配额。`scheduled` 和 `reassessment` 两种触发类型尚未实现。重新评估不创建扫描。修复复核已经写入 `verification`，但扫描本身不关闭 Finding。
